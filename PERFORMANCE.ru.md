# APC 3.11.0 — отчёт о производительности

## Исходная версия

`pawncc` вызывает компилятор из `pawnc.dll`. `sc2.c` читает исходники, обрабатывает include и макросы, выдаёт токены и ведёт таблицу символов. `sc1.c` и `sc3.c` разбирают объявления, операторы и выражения. Первый проход разрешает объявления и строит связи использования, затем компилятор удаляет неиспользуемые ссылки. Второй проход формирует промежуточный ассемблерный текст через `sc4.c` и `sc7.c`. `sc6.c` разрешает метки и записывает код, данные, метаданные и отладочную информацию AMX.

В исходном APC уже были все шесть перечисленных оптимизаций:

- `reduce_referrers()` хранит индекс символа и индекс слота обратной ссылки, строит списки смежности и обрабатывает очередь.
- `refer_symbol()` использует хеш-набор для поиска повторных ссылок. Вставка после поиска всё ещё сканировала массив в поисках свободной позиции.
- `max_stacksize()` использует итеративный обход, состояния посещения и кеш завершённых путей.
- Глобальный поиск символов использует хеш с проверкой полного имени и области видимости. Поиск вложенного измерения массива использует указатель на дочерний символ. Локальный поиск идёт от внутренней области к внешней.
- `findopcode()` ищет инструкции AMX в статической хеш-таблице. Метаданные AMX записываются из буфера.
- `assemble()` использует упорядоченный список для public-функций и индекс по числовому ID для native-функций. Кеш последней вставки сокращал обход глобального списка для возрастающих имён, но вставка произвольных имён оставалась квадратичной в худшем случае.

Инструментированная исходная сборка с `-O2 -d2` показала для `realistic_gm.pwn` 15,22 с в операциях с символами, 2,81 с в ассемблере, 1,87 с в peephole и 9,39 мс в `reduce_referrers()`. В `big_test.pwn` доминировал разбор, включая лексер и генерацию промежуточного кода. Таймеры вложены друг в друга и добавляют накладные расходы, поэтому их показания приведены для выбора участков работы. На цепочке из 20 002 функций исходный `max_stacksize()` занимал 1,07 мс. Итеративный обход сохранён, поскольку измерения не выявили основания для внедрения Tarjan.

## Реализованные оптимизации

| Участок | Изменение |
|---|---|
| `add_symbol()` | Хеш продолжает принимать глобальные символы сразу. Вставка в список ожидающих символов стоит O(1). Перед потребителем порядка список стабильно сортируется слиянием и объединяется с уже упорядоченной частью. Для пакета из k новых символов и n материализованных стоимость составляет O(k log k + n + k). Адреса узлов, порядок одноимённых символов и порядок локальных областей сохранены. Перед переименованием и удалением порядок материализуется. |
| `sclist.c` | Динамическая хеш-таблица с цепочками индексирует байты и длину префикса имени макроса. Коллизии проверяются сравнением префиксов. Паттерн и текст подстановки выделяются вместе с узлом. Проверены `#define`, `#undef`, повторное определение, вложенная подстановка и рост таблицы. |
| `find_constval()` | Таблица тегов получает индекс с открытой адресацией начиная с 32 записей. Максимальный ID тега сохраняется при добавлении, а порядок объявления сохраняется в списке для AMX. Для коротких таблиц, библиотек и временных списков сохранён линейный поиск. Константы Pawn, которые хранятся как символы, используют существующий поиск символов. |
| `refer_symbol()` | В массиве разделены выделенная ёмкость и занятый диапазон. Курсор первой свободной позиции обновляется при вставке и удалении ребра. Прежний порядок слотов сохранён. При невозможности увеличить хеш поиск переходит на массив. |
| `switch` | Сортированный буфер хранит пары «значение, числовая метка» вместо выделения узла на каждый case. До 32 записей помещаются в локальный буфер. Возрастающие метки добавляются напрямую, остальные требуют двоичного поиска и сдвига. Проверка дубликатов выполняется в позиции исходного объявления. |

## Замеры

Windows x64, AMD Ryzen 5 5600, исполняемые файлы Win32. Сборки APC выполнены MSVC 19.52.37029 через `build.bat` с `/O2 /GL /MT /DNDEBUG`. Для сравнения использована локальная копия [Pawn 3.10.8](https://github.com/pawn-lang/compiler/releases/tag/v3.10.8). SHA-256 её `pawnc.dll`: `00954BA399E4564A4E42CFDFFDA906A59551F88320418600070393A00213B813`.

Исполняемые файлы запускались из отдельных каталогов без собственного prefix include. Для всех компиляторов использовались одинаковые исходные пути, include и режимы. Время измерялось от запуска процесса до его завершения и включает ввод-вывод. `-e` направлял диагностику в файл. Эта опция пропускает финальную оценку стека, которую проверяли отдельно. В таблице приведены медианы успешных запусков. Основные большие тесты запускались по три раза, малый — семь раз, модульный — пять раз. Сырые времена, коды завершения, размеры и SHA-256 AMX находятся в [results.csv](benchmarks/results.csv).

- **Малый:** SA-MP include, макрос с параметром, короткий цикл и вызов native.
- **Модульный:** 24 отдельных include, 1 536 рабочих функций, 24 функции входа модулей, повторяющиеся имена статических массивов и более 1 500 макросов. Синтетический тест.
- **big_test.pwn:** поставляемый тест SA-MP с include-набором, крупным глобальным массивом и большой долей неиспользуемых функций.
- **realistic_gm.pwn:** 80 000 функций и вызовов, if/switch/for, строки и 7 000 000 ячеек. Вход восстановлен из шаблонов поставляемого BAT-генератора с нормализованными отступами и комментариями. SHA-256 входа: `0547465B20D6301199C88F14FB369E30A7D9D69EC5D4C15773359313AB73FEEA`.

Pawn 3.10.8 отклоняет `-fast` с кодом 3. На `realistic_gm.pwn` в остальных трёх режимах Pawn 3.10.8 завершился с ошибками 025 и 021. В `-fast` и `-d3` используется существующий переход к некомпактному кодированию с предупреждением 232. Размеры и хеши этих AMX сверены с исходным APC.

## Проверка релиза

- Чистая сборка `build.bat` создала `pawncc.exe`, `pawnc.dll` и `pawndisasm.exe`. Для всех трёх проверен формат PE x86.
- Сборка CMake Release с MSVC/Ninja прошла. CTest — 7 из 7.
- Расширенный PowerShell-набор прошёл. Проверены коллизии хеша символов, многомерные массивы, поиск include, прямой и взаимный рекурсивный вызов, цепочка из 20 000 вызовов и порядок 32 769 public-функций, объявленных в перемешанном порядке.
- Баннер выводит 3.11.0. Проверка `__Pawn == 779` прошла. Дизассемблер открыл полученный AMX.
- Проверки относятся к Win32 и перечисленным источникам. Сборка финальной ревизии на Linux и выполнение AMX внутри SA-MP/open.mp в эту проверку не входили.

## Оставшиеся возможности ускорения

На активно используемом коде стоит измерить повторное чтение промежуточного ассемблера при размещении меток и записи сегментов, включая повтор сборки при переходе к некомпактному AMX. Для больших `switch` со случайным порядком меток остаются сдвиги элементов. На проектах с большим числом небольших include-файлов следует отдельно проверить стоимость поиска путей и системных вызовов. Для больших локальных областей и частых удалений или переименований глобальных символов остаются линейные обходы. Профиль обычного проекта нужен, чтобы оценить стоимость каждого из этих участков до дальнейшей переработки.
