# APC 3.11.0 — исправление -Z и обновление

## Совместимость -Z

Прежняя проверка повторного подключения строила символ `_inc_` из фрагмента имени файла. Путь с `/` не разбивался по каталогу, а ключ усекался до длины идентификатора Pawn. Поэтому, например, `logic/inventory/inventory_items.inc` и `logic/inventory/inventory_var.inc` могли получить одинаковый ключ.

Для путей с каталогом и слишком длинных имён APC теперь хранит полный путь разрешённого файла в отдельной хеш-таблице. Хеш выбирает цепочку кандидатов, а полное сравнение строк проверяет совпадение. Нормализация учитывает `.`, `..` и варианты разделителя. Таблица очищается между проходами. Для коротких неполных имён сохраняются legacy-маркеры `_inc_*`, включая их видимость из Pawn. Проверки включают два файла с одинаковым basename в разных каталогах, общее длинное начало и подключение одного файла по эквивалентному пути.

Flin RP v2 проверен на копии реального проекта с явным `-Z+ -d3` и флагами задачи сборки. Три запуска завершились успешно. Предыдущий APC останавливался с ошибками неопределённых символов при тех же флагах. Итоговый AMX с -Z+ занимает 42 737 088 байт. При одинаковых остальных параметрах распакованные код и данные совпадают с предыдущим APC при -Z-. Конфигурация установленного проекта в этом обновлении не менялась.

## Перенос из Pawn 3.10.10

- #369 и #370. Пустые пользовательские сообщения больше не читают перед буфером. Диагностика неопределённого размера массива выводит имя символа.
- #371, #453 и #454. Передача признака записи в аргумент между реализациями по состояниям, исправление проверки переменной состояния и диагностика тегов в анонимном enum.
- #374, #397 и #451. Уточнения подсказок для функций, прототипов и состояний. Расстояние редактирования вычисляется в одной строке без выделения памяти на каждого кандидата.
- #375. `.lst` формируется на заключительном проходе, после разрешения объявлений.
- #377 и #378. Добавлены `#pragma unread`, `unwritten` и `nodestruct`.
- #421. Перенесены ограничение длины мнемоники и регистрация native-функций при обращении через `__emit`. Проверка длины в `#emit` уже была в APC.
- #424. Обновлён дизассемблер, в том числе обработка неизвестных инструкций и освобождение ресурсов на ошибках.
- #427 и #436. Неизвестные директивы в отключённых ветках игнорируются. Самоинициализация локальной переменной диагностируется.
- #445. Перенесён `__addressof`. Это имя становится зарезервированным, как в 3.10.10. Для запрета использования в препроцессоре в APC используется код 094, поскольку 093 занят проверкой длины аргумента `#pragma`.
- Объединение входных файлов сохраняет границы строк, проверяет запись и отслеживает имя собственного временного файла для очистки.

Проверка длины `#pragma option` (#462) уже была в исходной APC 3.11. Удаление ключевого слова `emit` из 3.10.10 не применено ради совместимости со старыми проектами APC. Перенос #421 частичный. Полный набор псевдоопкодов, изменения виртуальной машины из Pawn 4 и соответствующая поддержка нативных функций остаются самостоятельными задачами.

[Релиз Pawn 3.10.10](https://github.com/pawn-lang/compiler/releases/tag/v3.10.10).

## Производительность и проверка результата

Сохранены пакетная вставка и сортировка глобальных символов, хеши макросов и тегов, курсор списка ссылок, буфер меток `switch`, итеративный анализ стека и предыдущие оптимизации фаз компиляции.

- Поиск include использует рабочий буфер на стеке, выделяет имя только после успешного открытия и на Windows не делает отдельный `stat` перед `fopen`. Проверены порядок расширений и обработка отсутствующих `#tryinclude`.
- При сборке сегмента данных заранее известно, какими буквами могут начинаться его мнемоники. Остальные строки пропускаются перед разбором инструкции. Проход по коду сохраняет проверку инструкций.
- Компактный кодировщик записывает малые знаковые ячейки напрямую. Исправлено чтение перед большим буфером после заполнения групп. При повторной сборке без сжатия очищается таблица меток.

Режим -fast сравнивается отдельно между сборками APC. Официальные версии Pawn в этой серии запускались с -O2 -d0.

Windows x64, AMD Ryzen 5 5600. Все компиляторы сборки x86. Сравниваются официальные теги Pawn 3.10.8, 3.10.9 и 3.10.10, предыдущий APC 3.11.0 и этот релиз. Время включает запуск процесса и запись AMX. Исходники, рабочие каталоги, include и флаги одинаковы в пределах каждой строки. Сырые измерения находятся в [benchmarks/update-results.csv](benchmarks/update-results.csv). Для неточных сравнений на очень малом файле накладные расходы запуска сопоставимы со временем компиляции.

При -fast размер realistic_gm.pwn изменился с 50 199 308 до 15 568 906 байт. Старая сборка переключалась на некомпактный AMX. После декодирования сегменты кода и данных совпадают, как и длины сегментов и адрес входа.

Чистая сборка Win32 через `build.bat` и сборка CMake/Ninja прошли. CTest — **7/7**. Расширенный набор PowerShell прошёл, включая регрессии -Z, граничных значений компактного кодирования, рекурсии, цепочки вызовов и порядка public-функций. Проверка включает компиляцию и разбор AMX. Запуск gamemode в SA-MP/open.mp и сборка этой ревизии на Linux остаются отдельными проверками.

Ближайший резерв ускорения — повторное чтение промежуточного ассемблера и обработка очень больших списков include-путей. Для выбора следующего изменения нужны замеры отдельно на коде с большим количеством меток и на проектах с множеством отсутствующих необязательных include.
