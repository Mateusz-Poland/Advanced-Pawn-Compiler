# Advanced Pawn Compiler (APC)

**Advanced Pawn Compiler (APC)** — форк компилятора Pawn, ориентированный на ускорение сборки крупных проектов на Pawn, включая проекты SA-MP и open.mp.

> **Статус разработки:** этот снимок исходников относится к ветке 3.11.0 и является промежуточной dev-сборкой, а не финальным стабильным релизом. Перед использованием в production проверьте совместимость со своими проектами.

## Что входит в проект

- `pawncc` — консольный компилятор Pawn.
- `pawnc` — общая библиотека компилятора (`pawnc.dll` в Windows, `libpawnc.so` в Linux).
- `pawndisasm` — дизассемблер AMX.
- `include/`, `examples/`, `doc/`, `xml/` — include-файлы, примеры и документация Pawn.
- `source/compiler/tests/` — регрессионные тесты и PowerShell-скрипт дополнительных проверок.
- `benchmarks/` — большие тестовые исходники и генератор нагрузки на 80 000 функций.

## Основные направления оптимизации

В текущих исходниках присутствуют следующие изменения:

- **Peephole-оптимизатор:** индекс кандидатов по шаблонам, чтобы не перебирать полный список для каждой последовательности инструкций.
- **Анализ стека:** мемоизация нерекурсивных путей и итеративный обход длинных цепочек вызовов.
- **Обработка неиспользуемых функций и ссылок:** очередь в `reduce_referrers()` вместо повторного полного сканирования.
- **Лексер:** таблицы кандидатов по символам и предварительно вычисленные классы символов.
- **Обработка opcode:** ускоренный поиск и повторное использование найденных opcode.
- **Запись AMX:** буферизация вывода и блочная запись повторяющихся ячеек.
- **Ввод-вывод:** увеличенные буферы для исходников и временных файлов.
- **Поиск символов:** хеш-индексы для глобальных символов и повторных ссылок.

Это описание изменений в исходном коде, а не обещание конкретного процента ускорения. Результат зависит от проекта, параметров компиляции, платформы и файловой системы.

Список уже выполненных проверок и задач до стабильного релиза находится в [`docs/DEVELOPMENT-STATUS.md`](docs/DEVELOPMENT-STATUS.md).

## Совместимость

APC предназначен для сохранения совместимости с исходным кодом Pawn и форматом AMX при изменении внутренних алгоритмов компилятора. Побайтовое совпадение с каждой версией оригинального компилятора и для любых параметров не гарантируется. Перед публикацией сборки сравнивайте результат и, по возможности, запускайте AMX в целевой виртуальной машине.

Проект основан на исходниках Pawn и сохраняет исходные уведомления об авторских правах. APC является независимым форком и не является официальным релизом SA-MP, open.mp или ITB CompuPhase.

## Сборка из исходников

### Linux (CMake + GCC или Clang)

Требуются CMake, GCC и Make либо Ninja.

```sh
cmake -S source/compiler -B build/linux \
  -DCMAKE_BUILD_TYPE=Release \
  -DBUILD_TESTING=ON
cmake --build build/linux --parallel
ctest --test-dir build/linux --output-on-failure
```

Исполняемый файл компилятора появится в `build/linux/pawncc`; рядом будут собраны библиотека и дизассемблер.

Пример:

```sh
build/linux/pawncc -iinclude path/to/script.pwn -d2
```

### Windows (MSVC)

Скрипт `build.bat` собирает инструменты для Windows x86. Установите Visual Studio или Build Tools с компонентом **Разработка классических приложений на C++** и x86 MSVC toolchain. Запустите скрипт из обычной командной строки или x86 Native Tools Command Prompt:

```bat
build.bat
```

Результаты появятся в `bin\\`:

- `pawncc.exe`
- `pawnc.dll`
- `pawndisasm.exe`

Файлы `pawncc.exe` и `pawnc.dll` должны находиться рядом. Перед заменой компилятора в Pawno сделайте резервную копию старых файлов.

## Регрессионные тесты

CMake-тесты запускаются командой:

```sh
ctest --test-dir build/linux --output-on-failure
```

Дополнительный PowerShell-набор запускается отдельно в Windows:

```powershell
powershell -ExecutionPolicy Bypass -File source/compiler/tests/apc-regressions.ps1 `
  -Compiler .\bin\pawncc.exe `
  -OutputDirectory .\test-output
```

Скрипт создаёт временные исходники и AMX-файлы в указанной папке.

## Бенчмарки

Инструкции находятся в [`benchmarks/README.md`](benchmarks/README.md). Для честного сравнения используйте одинаковые исходники, include-пути и флаги, выполняйте несколько запусков и сравнивайте медианное время. Отдельно учитывайте холодный и прогретый кэш файловой системы.

Исторический скриншот в `benchmarks/historical-benchmark.png` сохранён как материал проекта, но не заменяет воспроизводимый отчёт о замерах.

## Версионирование

Для релизов используется схема `MAJOR.MINOR.PATCH`. Исходники 3.11.0 в этом архиве являются промежуточной dev-версией. Числовой макрос Pawn `__Pawn` использует кодирование major/minor, унаследованное от оригинального компилятора, и не является полной строковой версией SemVer.
