# Advanced Pawn Compiler (APC)

Форк компилятора Pawn 3.10.8, оптимизированный для сборки крупных проектов SA-MP и open.mp.

Этот компилятор создан для ускорения процесса разработки. В 2026 году, возможно, ещё остались монолитные модификации, переросшие 50 000 строк кода.
Возможно, в 2026 году ещё остались разработчики на Pawn.
APC решает проблему долгой компиляции, оптимизируя узкие места оригинального компилятора без изменения формата выходных файлов.

Около 75% кода в этом форке написано с помощью ИИ (Claude и Codex). Роль автора проекта заключалась в архитектурном планировании, профилировании, тестировании и обеспечении побайтового соответствия оригиналу. Базовый исходный код предоставлен [Zeex](https://github.com/Zeex/pawn) и командой [pawn-lang](https://github.com/pawn-lang) — без их работы этот проект был бы невозможен.

## 1. Сравнение производительности

Замеры проводились на синтетическом тесте (~800 000 строк, массивы на 7 млн ячеек, тысячи ветвлений `switch`).

| Версия компилятора 		| Время компиляции | 	   Прирост      |
| Оригинальный PawnCC 3.10.8    | 7.20 сек |       |          -         |
| ADV Pawn Compiler  		| 3.10 сек | 	   | ~58% (в 2.38 раза) |

(Скриншот с результатами теста: `bench.png`)

## 2. Основные изменения

Формат `.amx` и ключи командной строки не изменялись. Оптимизация затронула внутренние алгоритмы и работу с памятью:

*   Пептхол-оптимизатор (`sc7.c`): В оригинале на каждой строке перебиралось около 150 шаблонов (в сумме до 116 млн вызовов). Это занимало 67% всего времени компиляции. В APC шаблоны индексируются по опкоду, что сократило количество вызовов до ~3 млн.
*   Анализ стека: Устранен экспоненциальный перебор путей по графу вызовов. Для нерекурсивных функций применяется мемоизация. Это критически важно для функций с огромными конструкциями `switch`.
*   Удаление неиспользуемых функций (`reduce_referrers`): Квадратичный перебор заменен на очередь с сохранением логики.
*   Лексер (`sc2.c`): Внедрена таблица кандидатов по первому символу токена (вместо перебора всех 90). Парсинг чисел пропускается для токенов, не начинающихся с цифры. `alphanum` переведен на таблицу классов символов.
*   Ассемблер (`sc6.c`): Поиск опкодов осуществляется через хэш-таблицу (без `stricmp`). Опкоды запоминаются в первом проходе и переиспользуются в последующих.
*   Запись `.amx`: Около 40% инструкций в оригинале уходило на `fwrite` (по 4 байта). Теперь используется буфер на 256 КБ, а повторяющиеся ячейки (например, нулевые массивы) записываются блоками.
*   Ввод-вывод: Увеличен буфер чтения исходников и временных файлов (64 КБ). Отключены избыточные блокировки CRT (`_CRT_DISABLE_PERFCRIT_LOCKS`).

## 3. Совместимость и тестирование

На проверенных одинаковых настройках AMX сравнивается побайтово с оригинальным компилятором 3.10.8. Для больших таблиц символов и при ограничениях отладочного формата возможны различия, которые требуют отдельной проверки структуры и поведения AMX.

*   Для выпускной сборки требуется повторить полный набор сравнений с оригинальным компилятором на одинаковых входных данных и ключах.
*   Встроена защита от некорректной сборки: 64-битный компилятор просто не соберется.

## 4. Файлы в релизе

*   `apc3.11/` — Исходный код Advanced Pawn Compiler.
*   `build.bat` — Скрипт для сборки компилятора из исходников.
*   `sample_compile/` — Синтетический тестовый мод для бенчмарка.
*   `bench.bat` — Скрипт для одновременной проверки и сравнения скорости старого и нового компиляторов.

## 5. Установка

Просто замените `pawncc.exe` и `pawnc.dll` в вашей папке с Pawno. Сервер SA-MP или open.mp не заметит разницы, так как байткод остался прежним.

## 6. Параметры `-fast` и `-d3`

`-fast` ускоряет компиляцию за счёт отключения peephole-оптимизации. Полученный AMX может быть больше, а выполнение кода медленнее. Параметр соответствует `-O0` оригинального Pawn Compiler 3.10.8. Используйте его для быстрых локальных сборок, когда размер и скорость готового AMX менее важны. Обычная сборка использует оптимизацию `-O2`.

`-d3` добавляет подробные символьные данные для отладки. Это увеличивает размер AMX и может замедлить компиляцию. Если количество записей превышает ограничения формата отладочной секции, APC выдаёт предупреждение 240 и сохраняет AMX без этой секции. Для обычного релиза используется `-d2`.

Параметры поддерживаются компилятором, но не включены в настройки демонстрационного проекта. Проверка на локальном тесте многомерного массива показала побайтовое совпадение APC `-d3` с Pawn Compiler 3.10.8 `-d3`. Для APC `-fast` и оригинального `-O0` размеры и код AMX совпали. Один байт отладочной записи с именем файла отличался символом разделителя пути.
